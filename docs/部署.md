# 把 LitPilot 部署到一个固定地址

目标只有一个：**给评委/队友一个不会变的链接**，而不是每次演示前重新开一条隧道。
两条路都能走通，选一条就行；两条都准备好了配置文件，不用现写。

本文所有数字都是本机实测的（2026-11-22），不是估计。

---

## 0. 先选一条

| | Hugging Face Spaces | Fly.io |
|---|---|---|
| 费用 | 免费（CPU basic：2 vCPU / 16 GB） | 要信用卡，约 $3/月常开；suspend 后几美分 |
| 需要准备 | HF 账号 + 一个 write token | 信用卡 + 装 flyctl |
| 地址 | `https://<user>-litpilot.hf.space` 固定 | `https://litpilot.fly.dev` 固定 |
| 空闲行为 | 48h 无访问 sleep，冷启动 30–60s | suspend，冷启动 2–5s |
| 代码可见性 | public（免费档） | 私有 |
| 数据持久化 | 无（重启丢 trace） | 可加 1 GB volume |
| 国内访问 | 一般（Cloudflare 前置，多数可通） | 香港节点，通常更快 |
| 适合 | 现在就想给队友看、不想花钱 | 比赛当天当主入口 |

**建议**：先用 HF Spaces（零成本、十分钟能上）；如果比赛当天网络不稳，再花半小时上 Fly 当备份。两个地址都在，演示时哪个通用哪个。

## 1. 部署前必须做的两件事

1. **设访问口令**。链接一旦被转发，任何人点「运行」都在花你的 DeepSeek 额度：

   ```text
   LITPILOT_SHARE_TOKEN=<自己编一个，比如 litpilot2026>
   ```

   设了之后所有请求（含 SSE）都要 `?k=<口令>`，首访写 cookie，之后正常用。

2. **设每日额度闸**（默认 40，够彩排一整天）：

   ```text
   LITPILOT_RUN_BUDGET=40
   ```

   用完返回 429 并说明原因，不会默默烧钱。两个闸都在 `config.py` / `app.py` 里，不是靠人自觉。

> ⚠️ **`DEEPSEEK_API_KEY` 只能放在平台 Secrets 里**，绝不能进代码、README、Dockerfile。
> `.dockerignore` 已排除 `.env`，打包脚本也已排除，但你自己别手抖。

## 2. Hugging Face Spaces（推荐先做这条）

### 2.1 建 Space

打开 <https://huggingface.co/new-space>：

- Space name：`litpilot`
- License：随便（不影响构建）
- **Select the Space SDK：Docker** → **Blank**
- Hardware：**CPU basic · 2 vCPU · 16GB · FREE**
- Visibility：**Public**（免费档要 public）
- 点 Create Space

### 2.2 本地导出可推送的目录

```powershell
cd D:\lkj15\Documents\LitPilot
python scripts\hf_space_export.py
```

会生成 `dist/hf-space/`（34 个文件）。这个脚本干三件容易做错的事：

- 把 Space 必须有的 YAML frontmatter（`sdk: docker`、`app_port: 7860`）加到 README 开头，**README 只有一份**，不在两个仓库之间漂；
- 排除 `.env`、`.packages`、`data/`、`dist/`；
- 带上 `Dockerfile`、`requirements.txt`、全部源码与 `web/`。

### 2.3 拿 token 并推送

Token：<https://huggingface.co/settings/tokens> → New token → **Write** 权限 → 复制（只显示一次）。

```powershell
cd dist\hf-space
git init -b main
git add -A
git commit -m "LitPilot Space"
git remote add space https://huggingface.co/spaces/<你的用户名>/litpilot
git push space main
```

推送时 `Username` 填 HF 用户名，`Password` 填**那个 token**。token 就是密码，别写进任何文件。

### 2.4 注入 key（在网页上点，不走命令行）

Space 页面 → **Settings** → **Variables and secrets** → **New secret**：

| Name | Value |
|---|---|
| `DEEPSEEK_API_KEY` | `sk-...` |
| `LITPILOT_SHARE_TOKEN` | 你编的口令 |
| `LITPILOT_RUN_BUDGET` | `40`（可省，有默认值） |
| `LITPILOT_MOCK` | `0`（有 key 时本来默认就是 0，写上更明确） |

保存后容器会自动重启，Build 完成后地址是：

```text
https://<用户名>-litpilot.hf.space/?k=<口令>
```

`<用户名>` 里的大写和 `_` 会被转成小写/`-`，以 Space 页面顶部那个 "Embed this Space" 里的直链为准。

### 2.5 HF 上的四个坑（都会让人以为"部署失败"）

1. **容器以 uid 1000 运行**。如果 `/app` 属于 root，第一行 `mkdir data/runs` 就 `PermissionError`，日志还很难看懂。Dockerfile 里已经 `useradd --uid 1000` 并 `chown -R`，别删。
2. **端口必须是 7860**，且从 `$PORT` 读。`CMD` 用 shell 形式展开 `${PORT:-7860}`，改成 exec 形式就丢环境变量。
3. **文件系统是临时的**。重启/重建后 `data/runs` 清空，旧的回放链接 404。演示当天先跑一轮，别依赖昨天那条链接。
4. **免费档 48 小时没人访问会 sleep**。第一次打开要等 30–60 秒冷启动。比赛前 10 分钟点开一次预热，别让评委等。

真出问题就看 Space 的 **Logs**（Build 阶段失败看 build log，运行阶段失败看 container log）。我们全是纯 Python 依赖，不会卡在编译上。

**第五个坑：`Quota exceeded for flavor cpu-basic`（这个坑最坑，因为它看起来像部署成功）**

`git push` 成功、Space 页面显示文件、`/api/spaces/<user>/<space>` 返回 200——但状态永远是 PAUSED，打开网址 503 或停在 "Building"。
查状态方法（README 里不需要 token，公开 Space 就能查）：

```powershell
curl.exe -s https://huggingface.co/api/spaces/gloam05/litpilot/runtime
# {"stage":"PAUSED", "errorMessage":"Quota exceeded for flavor cpu-basic (requested=1): current=0, limit=0", ...}
```

`limit=0` 的意思是**这个账号没有免费的 CPU 硬件额度**，不是代码错、不是端口错、不是 Dockerfile 错。最常见的三个原因：

1. **邮箱没验证**——去 https://huggingface.co/settings/account 把邮箱验证了，再回 Space 的 Settings 点 Restart。
2. 账号被判定滥用（同一 IP 注册多个号、跑加密挖矿之类），额度被永久置 0。
3. 组织/团队 Space 要 PRO 才有 CPU basic。

处理顺序：验证邮箱 → Restart → 再查 `/runtime` 看 `stage` 是否变 `BUILDING`/`RUNNING`。还是 `limit=0` 就别在 HF 上耗时间了，
转 §3 Fly.io（要卡）或让我们本机 + 隧道顶着（§5 兜底顺序），**不要在演示前一天死磕平台**。

### 2.6 部署之后怎么改（改完怎么上线）

Space 本质上就是一个 git 仓库：**推一次 = 自动重建一次**。但改法有三条，别走错：

| 改法 | 适合 | 代价 |
| --- | --- | --- |
| 网页 Files → 点文件 → Edit → Commit | 改错别字、换一句话、临时救火 | 只存在于 Space，**本地仓库不知道** |
| 本地改源码 → `python scripts\hf_space_export.py` → commit → push | 所有正经改动（推荐） | 一次 3 分钟重建 |
| Settings → Factory rebuild | 构建卡住、依赖缓存脏 | 从零重建，最慢 |

**分叉规则（最重要）**：在网页上改的内容不会自动回到本地。下次跑 `hf_space_export.py` 会用本地文件覆盖掉它——所以网页上的改动要么当天就搬回本地，要么就当它不存在。搬回来的办法：

```powershell
cd D:\lkj15\Documents\LitPilot\dist\hf-space
git pull space main --rebase      # 把网页上那一笔拉下来
git log -1 --stat                 # 看改了哪几个文件，手动抄回 D:\lkj15\Documents\LitPilot
```

日常流程（改完上线）：

```powershell
cd D:\lkj15\Documents\LitPilot
python scripts\hf_space_export.py                 # 重新生成 dist\hf-space（保留 .git）
cd dist\hf-space
.\push.ps1                                        # 提交 + 推送（被拒会自动重试 --force）
```

`.\push.ps1` 由导出脚本带过去，作用就是 `git add -A` + `git commit` + `git push space main`，推送被拒时自动加 `--force`，失败时按错误信息给出对号入座的提示。**不要手打那串 git 命令**——这台机器的终端已经吞过字符，`git add -A && git commit` 打成了 `gi add -Agit commi`，PowerShell 把它当成 `Get-Item -Agit` 才报的那一串错。

**如果 `.\push.ps1` 被执行策略挡住**（报 `PSSecurityException` / "未对文件进行数字签名"），用同目录的 `push.cmd`——`.cmd` 不受执行策略管，双击也行：

```powershell
.\push.cmd
```

临时绕过（只对当前窗口有效，不需要管理员）：`powershell -ExecutionPolicy Bypass -File .\push.ps1`；
永久放行（需要管理员，改的是 CurrentUser）：`Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned`。

两个和这个项目特别相关的点：

1. **重建 = 新容器 = `data/runs` 清空**，昨天那条回放链接会 404。比赛/演示前 5 分钟不要推送，推送完先自己跑一轮把 trace 生成出来。
2. **secret 不会因为重建丢**（它们存在 Settings 里，不写进镜像）。所以 `.env` 永远不进 git，这一点已经由 `.dockerignore` 和导出脚本保证。

另外，我们这个 Space 一开始是用 **Static HTML 模板**建的（`README.md` 里 `sdk: static`，根目录还留着模板的 `index.html` / `style.css` / `.gitattributes`）。导出脚本已经把 `README.md` 的 frontmatter 换成 `sdk: docker` + `app_port: 7860`、并删掉那三个模板文件——**推上去之后 Space 会自动从"静态网页"变成"Docker 应用"**，看 Build 日志里出现 `docker` 字样就说明切过来了。如果 push 被拒（`non-fast-forward` / `unrelated histories`，说明本地这笔和远端不是一条线）：

```powershell
git push space main --force
```

## 2.7 换平台：Render（不绑卡，直接拿 HF 的公开仓库当源码）

**什么时候走这条**：HF 报 `Quota exceeded for flavor cpu-basic ... limit=0`，验证邮箱 + Restart 之后还是 `PAUSED`。
那是账号级限制，换 Dockerfile 没用，换平台最快。

关键在于 **Render 支持"Public Git repository"**，不需要 GitHub 账号、不需要把代码再传一遍——
我们的 HF Space 本身就是个公开 git 仓库，直接填它的地址：

```
https://huggingface.co/spaces/gloam05/litpilot
```

步骤（大约 5 分钟）：

1. https://dashboard.render.com/register 注册（邮箱就行，免费档不绑卡；如果某地区被要求绑卡，就回到 §5 的兜底顺序）。
2. Dashboard → **New** → **Blueprint** → 填 `https://huggingface.co/spaces/gloam05/litpilot` → **Apply**。
   仓库根目录的 `render.yaml` 会替你建好服务（Docker、Free、Singapore、健康检查 `/api/health`），
   只会弹两个输入框问 `DEEPSEEK_API_KEY` 和 `LITPILOT_SHARE_TOKEN`（`RUN_BUDGET` / `MAX_CONCURRENT` 已写死在 yaml 里）。
3. 等构建（首次 3–6 分钟）。地址形如 `https://litpilot-xxxx.onrender.com`。

如果 Blueprint 那条路被平台界面改了，退回手工五步：**New → Web Service → Public Git repository** → 粘同一个 URL →
Runtime 选 **Docker** → Instance Type 选 **Free** → 在 Environment 里加四个变量（`DEEPSEEK_API_KEY`、
`LITPILOT_SHARE_TOKEN=litpilot2026`、`LITPILOT_RUN_BUDGET=40`、`LITPILOT_MAX_CONCURRENT=1`）→ Create。

`/api/health` 是**故意不设口令**的：托管平台的存活探针带不了我们的 cookie，设了口令会永远 401，
平台就会判定容器不健康、反复重启。它只暴露"有没有配 key、今天还剩几次额度"。

拿到地址后按 §4 验三件事。注意事项：

- 免费档 **15 分钟没人访问就睡**，冷启动 30–60 秒（和 HF 的 48 小时睡眠比起来更勤，演示前 2 分钟点一次）；
- 免费档内存 512 MB，5 篇 PDF 顺序解析够用，但**别把 `PAPER_LIMIT` 调大**；
- 免费档的磁盘也是临时的，`data/runs` 重启即清空，结论和 §2.5 第 3 条一样：演示当天先跑一轮。

## 3. Fly.io（可选的稳定备份）

### 3.1 装 flyctl

```powershell
winget install --id Fly-io.flyctl -e
```

本机直连 GitHub 有时断，`iwr https://fly.io/install.ps1 -useb | iex` 可能失败，`winget` 更稳。
装完重开一个终端，`fly version` 有输出即可。

### 3.2 登录（要信用卡，验证 $0）

```powershell
fly auth signup     # 已有账号用 fly auth login
```

### 3.3 用仓库里现成的配置起应用

```powershell
cd D:\lkj15\Documents\LitPilot
fly launch --no-deploy --copy-config --name litpilot --region hkg
```

`fly.toml` 已经写好：香港区域、`internal_port 8080`、`/api/health` 健康检查、
`auto_stop_machines = "suspend"`（没人用时挂起，一有人访问就唤醒）、`shared-cpu-1x / 512MB`。

### 3.4 注入 secret 并部署

```powershell
fly secrets set DEEPSEEK_API_KEY=sk-... LITPILOT_SHARE_TOKEN=<口令> LITPILOT_RUN_BUDGET=40
fly deploy
fly open
```

地址：`https://litpilot.fly.dev/?k=<口令>`

### 3.5 想让回放链接活过重启，就挂 volume

```powershell
fly volumes create litpilot_data --region hkg --size 1
```

然后把 `fly.toml` 末尾 `[mounts]` 三行取消注释，并 `fly secrets set LITPILOT_DATA=/app/data`，再 `fly deploy`。

### 3.6 Fly 上的两个坑

1. **SSE 必须不被代理缓冲**。响应已带 `X-Accel-Buffering: no`，且每 20 秒发一次 keep-alive 注释行，足够穿过 Fly 的空闲超时。如果页面显示"跑完了但一格格没动"，就是这个环节，先在浏览器 Network 里看 `/stream` 是不是一次性到齐。
2. **`suspend` 不会掐断进行中的运行**：SSE 连接算活跃流量。但如果你把 `min_machines_running` 设成 0 又让机器睡过去，正在跑的那轮会中断——演示当天可以临时改成 1。

## 4. 部署完必须验三件事

```powershell
$k = "litpilot2026"
$base = "https://<user>-litpilot.hf.space"   # 或 https://litpilot.fly.dev

# 1) 活着、key 认到了、额度闸在
curl.exe "$base/api/health?k=$k"

# 2) 真实跑一轮（约 60–70 秒），看 SSE 是不是一条条出来
curl.exe -N "$base/api/runs/xxx/stream?k=$k"

# 3) 用浏览器打开首页，跑一轮，点表格里的证据，确认能跳到原文引句
```

第 2 步如果一次性刷完而不是逐条出，先怀疑平台代理缓冲，再怀疑我们的 keep-alive。

## 5. 钱和兜底

- 一轮真实运行：检索 5 篇（约 1.5 s）、下载 5 份 PDF（20–50 MB，20–50 s）、6 次左右模型调用。
  **实测**（2026-11-22，`deepseek-flash`，5 篇论文全链路）：**41.2 s、6 次调用、19,301 tokens、$0.0051 ≈ ¥0.036**（平峰价）。
  峰时（北京时间 09:00–12:00、14:00–18:00 的工作日）单价翻倍，约 **¥0.07 / 轮**——比赛演示正好落在峰时，按这个数做预算。
  余额 ¥12.93 够跑 **约 180 轮（平峰）/ 90 轮（峰时）**。
- 每轮的调用次数、token 数、美元成本都写在 trace 的 `metrics` 事件里（`Metrics.llm_calls / llm_tokens / cost_usd`），
  不靠估算：被问"跑一次多少钱"直接翻 trace 回答。
- ⚠️ **网页版 chat.deepseek.com 的额度与 API 余额是两套账**。网页版提示"使用额度已达上限"时 API 依然可用
  （2026-11-22 实测：网页版限流到次日 01:00，API `/user/balance` 返回 `is_available: true`、余额 ¥12.93，chat 调用 0.4 s 成功）。
  演示前查一次余额：`curl -H "Authorization: Bearer $env:DEEPSEEK_API_KEY" https://api.deepseek.com/user/balance`。
  余额低于 ¥5 就先充，别等演示当天。
- HF Spaces 免费档的额度是 CPU 时间，不是钱；Fly 按秒计费，挂起时不收。
- **兜底顺序**（演示当天）：Fly 定址 → HF Spaces 定址 → 本机 + `localhost.run` 隧道 → 本机 `127.0.0.1:8000`。
  最后一条永远可用，所以最坏情况也不会开天窗。
- 撤掉：HF 删掉 Space 就行；Fly 用 `fly apps destroy litpilot`（先确认名字，别删错应用）。

## 6. 一句话总结

想现在就让队友点开看：跑 `python scripts\hf_space_export.py`，push 到 HF Space，在 Settings 里填两个 secret，十分钟。
想要一个比赛当天更稳、能保住 trace 的地址：`fly launch --copy-config` + 两个 secret + `fly deploy`，半小时。
两条路都别忘 `LITPILOT_SHARE_TOKEN`——**公开链接 + 你的 key = 别人替你花钱**。

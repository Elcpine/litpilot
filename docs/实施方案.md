## 3. 指标口径（答辩必须一致）

- **CCR = A/B 级结论数 ÷ 结论总数**。分母是系统自己产出的结论，不含被丢弃的 D 级。
- **字段完整率 = (method ∧ dataset ∧ metrics 均非空) 的篇数 ÷ 参与抽取的篇数**。
- **证据等级分布**：按条统计 A/B/C/D，C 级必须能在表里看到（"已排除"），不能悄悄删掉。
- **人工评分**：20 条任务 × 3 人盲评 1–5 分（不看 trace，只看综述质量），报告一致性（Krippendorff α 或简单一致率）。
- **三组消融**：①单轮 RAG（10 篇摘要塞一次 prompt）②完整系统去掉 Critic ③完整系统。
  对比 CCR + 人工分 + 平均耗时。预期：①CCR 不可测（无逐条引用）②CCR 低 10–20 个点 ③最高但最慢。

## 4. 演示脚本（3 分钟）

1. **0:00–0:20 痛点**：三个 AI 给的综述，三条结论，两条翻不回原文。
2. **0:20–1:10 跑一轮**：输入题目 → 点运行。边跑边念 trace：
   "它在拆任务 → 检索到 5 篇 → 这篇下载超时了，它没有假装成功，降级用摘要继续，标 C 级。"
3. **1:10–1:50 看表**：指出 5 行里 1 行被标"已排除"，点开看引句与页码。
4. **1:50–2:20 复核**：Critic 发现 C 级 → 重拉全文 → 重抽取 → "C 1 条 → A/B 3 条"。这是系统自己在纠错。
5. **2:20–2:50 指标**：CCR 93.8%、字段完整率 100%、失败 1 次全部可见。
6. **2:50–3:00 落点**：不是更会写，是**每句话都能查**；trace 可回放，教学过程可复用。

## 5. 答辩 Q&A（含文档硬伤的应对）

| 问题 | 答法 |
|---|---|
| 你们说已完成原型，为什么现场才搭？ | 不辩解。说"文档写的是设计完成度，代码是这两天按文档落地的，字段、工具名、流程与文档一一对应"，然后立刻演示。**不要说"文档写错了"**。 |
| 为什么不用向量库？ | 跨篇要字段级对齐（method/dataset/metric 可比），相似度检索给不了对齐；chunk 相似度也无法支撑"这句结论出自哪一段"。 |
| CCR 的 ground truth 谁标？ | 20 条任务集人工双标 + 一致性系数；评测集与系统输出分离，标注者不看 trace。 |
| 中文文献呢？ | 检索后端抽象成可插拔接口（`search_papers` 一个函数），中文库需要授权；先用 arXiv 验证方法链，换库不改上层。 |
| "全部可离线缓存"和"调国产 API"矛盾吗？ | 缓存的是论文与解析结果；模型不可用时降级为规则抽取 + 预缓存结果，不承诺离线也能生成新综述。演示里断网跑的是预缓存那一轮。 |
| 和 Perplexity / Elicit / Consensus 的区别 | 它们给答案，我们给**可核对率**：逐条 A/B/C/D、页码、可回放的 trace、可复用的教学流程。 |
| 模型幻觉怎么办？ | 不靠模型自觉：引用句必须逐字，校验是确定性代码；对不上就降级，降级可见。 |
| 你们 CCR 都 100% 了，还测什么？ | 先承认口径：CCR 只测"引句能否在原文找到"，不测"引句是否支持这句话"。100% 说明模型抄引句很准，我们的价值在于**把这件事变成可测的数字**，而不是让它变难。真正的语义忠实度是下一层，我们用它做人工抽检（20 条任务集里每篇抽 2 条），报告里写明这是两种不同的检验。 |

## 6. 风险与砍单顺序

**最大风险：真实 PDF 解析质量**（双栏、公式、扫描版）。11.23 必须验证，不行就换 pdfplumber/PyMuPDF，
再不行就缩小到"arXiv 单栏论文"并在文档口径里说明范围。

砍单顺序（从先砍到后砍）：
1. 运行历史 / 动画特效
2. 真实模式 → 全部走预缓存
3. 20 条评测 → 10 条
4. 中文文献（本来就没做）

**绝不能砍**：trace 回放、证据分级、一次真实的失败与重试。这三个是"我们和聊天机器人不一样"的全部证据。
